# Корпусная редактура «Трафик → Чтение → Продукт»

Дата интеграции: 1 августа 2026 года.

## Источник решений

Единственный машинный источник маршрутов — `portfolio-routes.json`, раздел
`corpus_routing`. Для каждого из 24 индексируемых материалов там зафиксированы:

- уникальный запрос-владелец и поисковый intent;
- граница владения запросом;
- редакционный приоритет `P0/P1/P2`;
- три смысловые внутренние ссылки с отдельным анкором и причиной;
- аудитория;
- один доминирующий CTA и не более одного вторичного;
- продукт, вариант CTA и уникальный смысловой мост.

Порядок assets больше не влияет на перелинковку. Публичного маршрута `TEST` нет.
Индивидуальная работа и Навигатор не используются как маршрут статей.

## Волны проверки

1. Базовая линия строится командой `npm run archetypes:baseline`. Результат —
   `00-baseline.csv`. Если экспортов Search Console, Яндекс Вебмастера или GA4
   нет, соответствующие поля остаются `n/a`.
2. Независимые аудиты всего корпуса проверяют поисковое владение, граф ссылок и
   продуктовые маршруты. Их решения интегрируются только через
   `corpus_routing`.
3. Один интегратор изменяет manifest, генератор, аналитику и статьи. Ручные
   правки итогового HTML не являются источником правды.
4. Красная команда читает только конечный HTML и возвращает `PASS` либо
   `REOPEN` с URL, приоритетом и проверяемым условием закрытия.

## Внедрённый контракт HTML

В каждой статье внутри `<main>` есть отдельный `.article-product-cta`, который
расположен перед блоком связанных материалов. Он содержит:

- `data-route-id`;
- `data-product-id`;
- `data-cta-variant`;
- `data-placement`;
- один визуально доминирующий переход;
- максимум один вторичный переход.

Ссылки на связанные материалы создаются только из явной матрицы. Они несут
`data-related-route-id` и не засчитываются как продуктовый CTA.

## Аналитика

После согласия на аналитику работают события:

- `article_view`;
- `related_article_click`;
- `cta_impression`;
- `product_click`;
- `lead_start`;
- `lead_submit`.

Все шесть получают `route_id`, `product_id`, `cta_variant`, `placement`.
Атрибуция сохраняется в рамках сессии и дублируется безопасными параметрами
перехода на внутреннюю продуктовую страницу.

`lead_submit` готов принимать фактическое подтверждение через событие
`eh:lead-success` или submit собственной формы. Подтверждение заявки во внешнем
GetCourse, оплаты в Stripe или разговора в Telegram требует их success callback,
thank-you page либо webhook; обычный исходящий клик не считается отправленной
заявкой.

## Приёмка

Обязательный набор:

```text
npm run archetypes:generate
npm run archetypes:baseline
npm run archetypes:check
npm run archetypes:responsive
npm run analytics:smoke
npm test
git diff --check
```

`archetypes:corpus-audit` проверяет 24 уникальных query owner, продуктовый путь
внутри `<main>`, явный граф, минимум два входящих контекстных ребра, отсутствие
публичного теста, мужской маршрут S04 и аналитический контракт.

## Наблюдение после публикации

- Сразу: HTTP, canonical, sitemap, indexability, битые ссылки и события в
  браузере.
- Через 30 дней: запросы, показы, CTR, позиции и первые `product_click`.
- Через 60–90 дней: рост органического трафика, каннибализация, assisted
  conversions и переход от двухнедельного входа к интересу к менторингу.
- Числовые цели назначаются только после появления фактической базовой линии.
