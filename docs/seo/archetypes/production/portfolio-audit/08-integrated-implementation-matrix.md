# Единая матрица внедрения портфельного аудита

Дата: 27 июля 2026.

Статус: **нормативная карта правок 26 существующих черновиков**.

Эта матрица сводит:

- SEO ownership и перелинковку;
- коммерческий маршрут;
- человеческий голос и лёгкость чтения;
- уместный юмор;
- доверие и safety.

Если рекомендации отдельных аудитов конфликтуют, применяется эта матрица.

Продуктовые ссылки в Markdown фиксируют целевой маршрут, но не разрешают
публикационную активацию сами по себе. В HTML продуктовый CTA рендерится только
после `safety_normal + product_interest + product_active + audience_fit`;
иначе блок скрывается без автоматической замены другим продуктом.

## 1. Общие решения

### 1.1. Финальный маршрут

| Тип | Статьи | Главный destination |
|---|---|---|
| Персональная карта | 02, 03, 04, 05, 06, 11, 13, 14, 15, 19, 21 | `/test-arhetipov/` |
| Двухнедельный вход | 01, 07, 08, 12, 16, 22, 25, 26 | `/lightness/#bundle` |
| Женский менторинг | 17, 23 | `/mentoring/` |
| Навигатор | 10, 24, 27 | `/pervyi-shag.html` |
| Следующая статья, без коммерции | 09, 18 | R06 для 09; L08 для 18 |

Ретрит не является прямым CTA холодной SEO-статьи. Он появляется после
квалификации зрелого живого перехода через Навигатор или интерфейсный выбор.

### 1.2. Квалификационный мост

Продуктовая ссылка не ставится сразу после описания боли. Перед ней должны быть:

1. самостоятельная польза;
2. safety-развилка;
3. один вопрос, который подтверждает намерение.

Для двухнедельного входа:

> Если одного наблюдения пока достаточно, можно остановиться здесь. Если
> хочется не длинной программы, а короткого живого опыта, посмотрите
> двухнедельный вход «Вкус лёгкости + Вкус силы».

Для менторинга:

> Если эта тема повторяется в нескольких сферах, хотя вы уже многое понимаете и
> пробовали менять, её можно взять как одну ключевую задачу в женский менторинг.

Это смысловые модели, не шаблоны для дословного копирования.

### 1.3. Контракт теста

- Полный публичный контракт остаётся в 11 и на странице теста.
- В 21 остаётся только специфика мужской системы и короткая схема расчёта.
- В 02–06 и 13–15 остаётся 4–6 предложений: точные данные, натальная карта,
  три упорядоченные роли, первая рабочая интерпретация, тема отдельно.
- В жизненных статьях остаётся 2–4 предложения: текущая ситуация не определяет
  код; без точного времени расчёт не выполняется; подробности — по ссылке.
- Технические слова `Плацидус`, `исторический часовой пояс` и
  `генеративная модель` не повторяются во всех жизненных статьях.

### 1.4. Голос

- Переименовать все 25 H2 `Один следующий шаг` в содержательные.
- В женских role-pages сцена идёт раньше словарного определения.
- Не более одной полной рамки метода и одного safety-блока на статью.
- Сократить серийные `не X, а Y`, сохранив реальные защитные ограничения.
- Не добавлять вымышленные реплики, кейсы и счастливые финалы.

### 1.5. Юмор

Юмор внедряется только как точная бытовая деталь. Приоритетные статьи:

- 01: макраме получило бизнес-план раньше, чем вернулось в руки;
- 02: маленькое желание успело пройти проверку на талант, доход и пользу;
- 05: план на двадцать лет не обязан лежать в ламинированном виде;
- 12: свободный вечер не нужно превращать в проект правильного отдыха;
- 23: формально продукты купил другой, диспетчер задачи всё ещё вы;
- 25: пробный урок не требует предварительно стать концертным человеком;
- 26: отдых, которым продолжают эффективно руководить;
- 27: двадцатый критерий не добавляем, проверяем один факт.

В safety-блоке, абзаце перед ним и двух абзацах после него юмор запрещён.

## 3. Порядок внедрения

### Партия A: 01–09

- сценические входы role-pages;
- сжатие тестовых блоков;
- разведение L03/L12;
- 2W для 01, 07, 08;
- без коммерции в 09;
- внутренние ссылки по SEO-матрице.

### Партия B: 10–18

- NAV для 10;
- полный контракт только в 11;
- 2W для 12 и 16;
- MENTORING для 17;
- ARTICLE-маршрут для 18;
- role-pages 13–15 со сценическими входами.

### Партия C: 19, 21–27

- облегчение справочных 19 и 21;
- 2W для 22, 25, 26;
- MENTORING для 23;
- NAV для 24 и 27;
- входящие ссылки на поздние сироты.

Партии могут редактироваться параллельно, потому что не пересекаются по файлам.
После объединения выполняется общий корпусный аудит.

## 4. Acceptance

- в папке ровно 26 drafts;
- у каждого один главный следующий шаг;
- распределение: 11 TEST, 8 2W, 2 MENTORING, 3 NAV, 2 ARTICLE;
- нет прямого RETREAT CTA;
- нет упоминания Маргариты;
- все поздние indexable-страницы получают входящие ссылки;
- L03 больше не владеет полным delegation how-to;
- полный тестовый контракт не повторяется в жизненных статьях;
- H2 `Один следующий шаг` остаётся максимум в 30% корпуса;
- не более одной полной safety-оговорки и одной рамки метода на статью;
- product CTA стоит только после самостоятельной пользы и safety-развилки;
- женский mentoring назван женским и не выводится из пола/системы автоматически;
- даты, цены и срочность отсутствуют в evergreen-статьях;
- машинный аудит не находит Margarita, диктовочных маркеров и запрещённых
  формул теста.
