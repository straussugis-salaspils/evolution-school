# Портфельный SEO-аудит: ownership, каннибализация и внутренняя перелинковка

Дата проверки: 27 июля 2026.

Статус: read-only аудит 26 фактически существующих черновиков. Черновики в ходе этой проверки не изменялись.

## Источники и ограничения

Проверены:

- все Markdown-файлы `docs/seo/archetypes/production/drafts`;
- соответствующие производственные брифы;
- `00-real-test-contract.md`;
- `15-test-production-sequence.md`;
- `16-unified-routing-matrix.md`;
- документы `content-universe`, особенно карта консолидации и authority-архитектура.

Wordstat и SERP заново не проверялись. Этот аудит не добавляет новых частот, не суммирует показатели из брифов и не переоценивает URL-гейты без новых поисковых данных.

## Резюме

Корпус в целом имеет устойчивый intent ownership. Массово объединять статьи не нужно.

Главные проблемы:

1. В корпусе 26, а не 30 реальных черновиков: 01–19 и 21–27.
2. Все 26 страниц ведут в `/test-arhetipov/`, но сам локальный destination пока отсутствует.
3. Локально отсутствуют также `/arhetipy/` и `/zhenskie-arhetipy/`, на которые уже поставлены 14 ссылок.
4. Граф сильно смещён к ранним статьям. Семь поздних материалов не имеют ни одной входящей ссылки из других черновиков.
5. L03 «Устала быть сильной» забирает существенную часть практического ответа L12 «Всё делаю сама».
6. Полный контракт натального расчёта повторяется почти во всех статьях одинаковыми абзацами. Это не отдельная поисковая каннибализация, но большой объём шаблонного текста ослабляет уникальный ответ каждой страницы.
7. SEO-метаданные хранятся непоследовательно: YAML есть только в черновике 06, у S04 и S06 в брифах не зафиксированы Route ID и canonical в стандартном поле.

Решение:

- сохранить 26 URL;
- развести одну критическую пару редакционно;
- добавить контролируемые входящие ссылки на поздние страницы;
- превратить S02 `/arhetipy/`, S03 `/zhenskie-arhetipy/`, S04 `/muzhskie-arhetipy/`, S05 `/arhetipy/chto-eto/` и S06 `/arhetipy/resurs-i-ten/` в ясную систему hub → cluster → article;
- не публиковать статьи с активными ссылками на отсутствующие destinations;
- сократить повторяемый контракт теста по типам страниц, не меняя его фактов.

## Повторяемый тестовый блок

Машинная проверка нашла:

- одинаковую фразу об отсутствии точного времени — в 21 статье;
- одинаковую строку о входных данных — в 13 статьях;
- одинаковые абзацы о трёх позициях — сериями по 3–8 статей;
- одинаковые формулы о Плацидусе, генеративной модели и «первой рабочей сборке».

Это нормативно верные факты, но не все статьи должны повторять полный технический контракт.

Точная система:

1. S01 `/test-arhetipov/` и S05 `/arhetipy/chto-eto/` содержат полный публичный контракт.
2. Role-pages содержат короткий блок: точные данные → натальная карта → три упорядоченные роли → первая рабочая интерпретация.
3. Life-pages содержат только то, что нужно для перехода: тест не диагностирует текущую тему; без точного времени расчёт не выполняется; текущая тема выбирается отдельно.
4. S04 и S06 объясняют только свою специфическую часть результата и ссылаются в S05/S01.
5. Safety-формулировки не сокращаются механически там, где тема чувствительная.

Цель — убрать дословные дубли, не потеряв ни одного факта из `00-real-test-contract.md`.

## Метаданные

### P0: единый источник

Сейчас только `06-gera.md` содержит YAML:

```yaml
route_id: R05
canonical: /arhetipy/gera/
seo_title: ...
meta_description: ...
status: draft
```

Остальные черновики начинаются сразу с H1. Нельзя строить публикационный pipeline, который случайно прочитает метаданные только у статьи 06.

Нужно выбрать один вариант для всех 26 активов:

1. единый front matter во всех drafts; или
2. отдельный машинно-читаемый manifest с route ID, canonical, title, description, index state и source file.

Брифы остаются редакционным источником, но не должны быть единственным runtime-источником SEO-тегов.

### P0: отсутствующие стандартные поля

### P1: title preview

Перед публикацией проверить по пиксельной ширине, а не только по числу символов. Наиболее вероятно обрежутся рабочие title у 04, 07, 08, 09, 10, 11, 17 и 22.

## Критерии повторной проверки

Аудит считается закрытым, когда:

- в manifest ровно 26 активов и нет вымышленных «статей 20, 28, 29, 30»;
- каждый актив имеет уникальные Route ID, canonical, SEO title и meta description;
- все публичные destinations возвращают 200;
- каждый indexable URL имеет self-canonical и присутствует в sitemap;
- ни одна indexable статья не является сиротой;
- S03 ссылается на все восемь женских role-pages;
- S04 не создаёт тонкие мужские role-pages;
- L03 не содержит полный алгоритм, принадлежащий L12;
- L01/L02/L14/L15 и L03/L04/L10/L12 имеют явные текстовые границы и взаимные переходы;
- S05 и S06 не дублируют полный ответ друг друга;
- на обычной статье остаётся не более трёх основных переходов к чтению; системные hub/pages могут быть исключением;
- test CTA активируется только после появления и QA `/test-arhetipov/`;
- полный crawl не находит 404, redirect loops, canonical mismatch и `index` на персональных результатах;
- после 8–12 недель выводы подтверждены Search Console, а не предположением.
